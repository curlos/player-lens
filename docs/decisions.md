# Decisions log: why we chose what we chose

> Context that was discussed in planning but isn't in PRODUCT or ARCHITECTURE. If a decision here conflicts with those, flag it; don't silently pick one. Open (unanswered) decisions are in TASKS.

## World and naming

- **League:** Atlas League (owner's choice; a generic word).
- **Teams:** Azure City (AZC, blue) and Redmond United (RDM, red).
  - "Azure" is also an ordinary color and word, and the judges are Microsoft people who will get the wink.
  - Rule 11.8 reserves Microsoft's and the Premier League's IP "to the extent provided for in these Official Rules", and the rules say nothing about club names, so this is a gray area. Risk is low; keep it safe by using "Azure" only as a color/club name, with no Azure logo or product styling in the UI or video.
  - "Redmond" is Microsoft's HQ city (a place name, not a trademark). Don't name clubs after products (Copilot, Foundry, Fabric).
  - The mockup's AZU/CRC abbreviations are replaced everywhere by AZC/RDM.
- **Names:** all fictional, mixed nationalities, as a real league would have. A famous-player blocklist check is part of the roster generator (not built yet). Overlapping surnames are fine; real full names are not. An AI can't guarantee a name isn't some obscure real pro, so the owner spot-checks the final list.
- **Squads:** 11 starters, no bench, no substitutions (stale earlier note said about 5 bench players; the roster spec and `sim/models.py` have exactly 11 per team).
- **Redmond's formation:** 4-4-2, for tactical contrast with Azure's 4-3-3 (decided).
- Gender field: every player has gender (default `male`); all generated players are male for now. User-facing copy stays gender-neutral.

## Scope

- **2D dots, not 3D:** cheaper and more reliable in 3.5 days; the value is the data and explanations.
- **Two clubs, not a 20-team league.** A league table with about 20 fictional club names and a scoreline-only season sim (about 30 minutes) is a stretch feature and the first thing cut after the extra matches.
- **Match library: three matches**, all Azure City vs Redmond United on different matchdays: the hero (3-2, matchday 38), a blowout (4-0 or 5-0) and a 1-1 draw. A 7-0 was rejected as too rare to produce realistically. A 0-0 is an optional fourth. Validation runs are code only (no LLM calls); 10-20 seeds is plenty for the report, and 200+ for calibration.
- **No halftime:** Azure attacks left to right the whole match; sides never switch.
- **Personalizer** is added as a stage (matches the "personalize" pipeline stage). It's the same LLM call with a mode and language instruction, not a translation library, so the extra cost is negligible. Decided Oct 24: it is a separate agent. The Commentator writes one canonical line per moment, Fact Guard checks it once, and the Personalizer makes the four variants, so the Commentator and Fact Guard do not run four times; a code check confirms every number and name in a variant appears in the checked facts.
- **Deploy on Azure Container Apps**, not Vercel (even though the owner usually deploys on Vercel). One Docker container serves the API and the built React app.

## Data and simulation

- **Python for the simulator:** numpy, Pydantic and the Agent Framework Python SDK keep the backend one language. React stays on the frontend.
- **Run offline, serve files.** Simulating is fast; the reason to run it offline is that every visitor sees the same fixed match and the commentary is written against exactly those events. The browser downloads four static files per match (`meta`, `events`, `ratings`, `positions`) and plays them back locally, so there is no SSE.
- **Code makes the numbers, LLM makes the words.** A Monte Carlo simulator is just weighted dice per event, repeated; the seed makes it repeatable.
- **Two-step events (decide, then execute)** borrowed from Football Manager. EA's engine internals are unpublished, so we borrow EA's attribute structure, not its engine.
- **Attributes:** final list confirmed Oct 24: Pace, Passing, Vision, Finishing, Dribbling, Defending, Positioning, Composure, Strength, Work rate, Stamina, Set pieces, plus GK Shot-stopping for keepers. Acceleration is derived from Pace; Anticipation is folded into Positioning. Fuller set in the attributes research doc.
- **No teleporting** is guaranteed by construction: positions change only in `move_player()`, speed-capped. Property tests (not written yet) will check it.
- **Pitch:** 105 x 68 m, meters, origin top-left; the SVG uses `viewBox="0 0 105 68"` so data and screen can't disagree. Positions are saved every second, compactly (flat integer arrays in decimeters); the frontend interpolates between them.
- **Pydantic design:** `extra="forbid"` so typos fail loudly; `team.short` duplicates `team.id` but is validated to match; goalkeeper-only `gk_shot_stopping` lives on Player; attributes are nested under `attributes`.

## Phase 1 build (Oct 25)

Choices made while building the match data, where the docs left room or disagreed. All knobs live in `sim/config.py` and `rating/config.py`.

- **Star name (owner decision).** The star is AZC #9 (`azc_09`), the highest-OVR Azure player, named by the generator like everyone else (Gabriel "G. Lima", Brazil). "R. Valdemar" in the frontend spec, match-files example and mockups was a placeholder; those specs now point at `data/world.json`.
- **Event ids** follow Spec: Match Files (`e_0001`), not ARCHITECTURE's illustrative `ev_1843` (ARCHITECTURE updated).
- **Event count** is about 4,500 to 5,500, not 1,500 to 2,000: every rating entry must point to an event, so the 30 to 45 s shape checks are events (roughly half the file). A shape check is added only when a player has had no other rating entry for 30 to 45 s.
- **Bench:** the "11 starters plus about 5 bench players" line above is stale; the roster spec and models have 11 per team and no bench.
- **Sent-off players** walk (via `move_player()`) to the bottom touchline (y = 68, x = 45 for Azure, 60 for Redmond, set in `sim/config.py`), away from the score bar at the top center, and stay there with a new activity code `sent_off`, so every position stays on the pitch. The frontend fades the dot out once they arrive (owner decision Oct 26). If a back-four player is sent off, the DM/CM #6 takes their slot.
- **Shot speed** is capped at 108 km/h, because the ball cap is 30 m/s (the spec example shows 112).
- **Blocklist** syntax: one word or `surname: X` blocks a surname, two or more words block a full name. Famous surnames from the pools (Van Dijk, De Jong, De Vries, Gomes) are blocked so no player reads as a famous one.
- **Stopping rule** uses the exact per-tick braking sum (the spec allows "a short loop or closed form"); the `u (u + a) / (2a)` approximation let players overshoot touchlines. A per-axis wall cap keeps the acceleration limit true at the lines too.
- **Calibration changes beyond the research formulas** (see `docs/validation-report.md`): pass completion gets a receiver-marking term and a harder "pass into the box" term; crosses complete less often; a goal-side defender stops a carrier running straight at goal; near their own goal the two nearest defenders always press. Passing and duel skill sensitivity were softened (`PASS_Z` 0.18, `DUEL_SKILL` 0.22) and Redmond's tactics set to press 0.5, line 0.45 (still a deeper block than Azure's 0.8 and 0.7) so a title decider between first and second is not one-sided: Azure win about 58%, draw 22%, Redmond 19% over 200 seeds.
- **Pressure** counts a presser closing in (moving at 3+ m/s) within 1.1 m of the carrier, once per presser and carrier per 30 s; this lands pressures per team inside 115 to 175.
- **Rating tuning (first pass):** repeat decay `max(0.25, 0.85^n)`; shape-check credit +0.02 only for staying within 3 m of the shape target while working; a pressure regain needs the presser within 10 m of the ball when it is won. Mean final rating about 7.0 (SD 0.8).
- **Accepted as is (owner, Oct 26):** ratings run slightly high (mean about 7.0 vs about 6.7 on real sites), and the simulator produces too many duels (a striker can attempt about 20 dribbles a match vs 2 to 4 in real football; repeat decay keeps the rating effect small). Fixing duels would change every match and the library seeds, so neither is tuned further for the hackathon.
- **Off-ball thresholds** (recovery run 12 m in 8 s ending goal-side, marking denial 2.5 m for half of a 5-minute window with no pass received, decoy run drags a defender 6 m while a teammate gets 4 m of space) are guesses, listed in `rating/config.py`.
- **Penalty event** is logged when the penalty is awarded (outcome `awarded`); the kick itself is a `shot`. Other restarts are logged when taken.
- **Library seeds** come from `scripts/find_seeds.py` (criteria in its docstring) and are stored in `sim/library.py`.
- **Hero match (owner pick, Oct 26):** seed 9447. 2-2 after Redmond's 88' equaliser, then Lima's 89' title winner; Azure play with 10 men from 51' (J. Pereira, second yellow). The exact "2-2 from mid-match until a winner after 85'" pattern was not found in 16,000 seeds; the two closest both had a late equaliser, and 9447 was picked because the climax belongs to the default player. The first hero (seed 2378: Lima twice, 83' penalty winner by M. Thomas) is kept as `md38_title_decider_backup`, built and tested but not listed in the picker. Any change to the world or the simulator changes every match, so re-run the search after one.

- **Spells built early (Oct 26):** `rating/spells.py` labels each 5-minute window (`control`, `high_press`, `end_to_end`, `even`) from `events.json` only, so the agent pipeline can call it at runtime without positions. Not written into the match files (the four-file contract stays as is). Thresholds are guesses tuned to the library matches.

## Playback controls (owner, Oct 26)

- **Speeds are 1x, 2x, 4x, 10x, 30x** (was 1x-10x in six steps), copied from the dev viewer so a full match can be skimmed in 3 minutes. Commentary still plays at 1x only.
- **Highlights row** below the pitch: goals, cards and penalties as chips; a click seeks to 8 s before the event so the build-up plays. Labels use the football minute (87:12 shows as 88').
- **Activity labels**, off by default: every dot shows what that player is doing (jog, hold shape, press...). Moved from the control bar into the View popover (owner, Oct 26), and with it off the followed player shows no activity either: the commentary already says what they are doing.
- **Shirt numbers in highlight chips** (`88' GOAL #10 J. Ribeiro`), because the pitch shows numbers, not names.
- **Hover tag** on any player dot: number, name, position, OVR and live match rating. Frontend only; the data is already in `meta.json` and `ratings.json`.

## Phase 2 build (Oct 26)

Choices made while building the match viewer (`web/`), where the docs left room. Knobs live in `web/src/lib/config.ts`.

- **Start overlay copy** follows PRODUCT's intro text, not the mockup's three bullets. The standings snippet (owner decision Oct 26) has Redmond 1st on 85 points and Azure 2nd on 84, so Azure must win the title decider; a draw or a loss leaves Redmond champions. PRODUCT's intro copy was updated to match. The numbers are one static constant (`STANDINGS`), never simulated.
- **Spotlight** turns on for about 7 match seconds after a big moment (importance 0.8 or more) of the selected player and for 2.5 s after a click selects someone (owner, Oct 26: the dim is instant, then eases out: after a click it holds 1.5 s and fades back over 1 s; after a big moment it fades over the last 1.5 match seconds); otherwise nobody is dimmed. This reconciles PRODUCT ("click a player: others dim") with the frontend spec ("normal view dims nobody").
- **Second yellow:** the yellow and the red share a second; the highlights row, the timeline, the card caption and the commentary show only the red.
- **Every rating change is commented (owner, Oct 27).** The ±0.10 trigger is gone: any non-zero rating-log row, positive or negative, for any player, gets a line, because the full run showed Lima's dispossessions (-0.08) were never mentioned and only good news was. A row too close to the previous line waits up to 10 s (`RATING_MAX_DELAY_S`) or joins the previous rating line; it is never dropped. Templates have separate frames for a change that went down, so a fallback never praises a dispossession.
- **Rating pops:** every change for the selected player, but only changes of 0.05 or more for others (`POP_MIN_DELTA_OTHERS`): the simulator's many small duel credits otherwise covered the action in a cloud of +0.01s.
- **Selected player's rating** sits in their name tag (spec: "with Show ratings off only the selected player's rating shows").
- **Show ratings** adds pills only; the mockup's recolored dots are not copied (team colors stay readable).
- **All ratings** has no "Pitch | List" toggle (mockup only); the slot layout is presentation code because `FORMATION_XY` is not in the match files. The sent-off player stays in the lineup, greyed with a red card.
- **Player card** shows the formation slot (RB, LW) next to the number, as the hover tag does, because `position` is coarse (FB, W).
- **Commentary placeholder** builds lines in code from the player's events and rating log with the decided cadence (5 s minimum gap, 15 s maximum silence, a reaction 8 s after a goal). Filler lines use the current activity, distance and rating. All behind `getCommentaryChunk` / `getTrace`, which Phase 3 replaces.
- **Full-time recap** is a code template from goals, assists, distance and off-ball credit until `GET /recap` exists.
- **Spanish variant (owner, Oct 26):** one variant, Latin American aimed at Mexico, matching ESPN Deportes, TUDN and Fox Sports México: atajar/atajada, fuera de lugar, penal, pelota (owner preference over balón), disparo, portería, and portero (Mexico says portero, not arquero). Chosen for the larger Premier League audience in Latin America and US Hispanics. Phase 3 should use an `es-MX` voice so the accent matches the wording.
- **Keyboard and screen readers (owner, Oct 26):** the pitch is a single tab stop with arrow-key movement between nearby players (nearest ahead within about 63 degrees, sideways offset counted double), not 22 tab stops. Focus moves are announced by the screen reader itself; commentary and goal announcements use polite live regions, which screen readers queue until the user pauses, so navigation always speaks first.
- **Goalkeeper colors (owner, Oct 26):** gold and pink for everyone, replacing neon yellow and orange, so the keepers stay distinct for colorblind viewers (see `KEEPER_COLORS`). Blue and red kits are unchanged: they stay clearly distinct under all three main types of color blindness.
- **Movement arrows (owner, Oct 26):** a small, sharp, filled triangle growing out of a moving dot's outline (white; lime out of the followed player's lime ring), pointing where the player is heading. Direction only: on a moving screen the motion already shows speed. Shown by default only for the followed player (lime) and the 5 players nearest them within 25 m, the ones reacting to them; everyone else is opt-in (All movement arrows). Tried and dropped on the way: an arrow with a shaft (on a round dot it read as an unintended shape), speed lines behind the dot (redundant with the motion), and an arc on the dot's front edge, with and then without the arrowhead (too busy).
- **Type sizes (owner, Oct 26):** 14 px for readable text and a 12 px floor for labels, after common guidance (WCAG sets no minimum; design guides put readable text at 14 px or more and captions at 12 px or more). The sidebar grew to 360/400 px to fit.
- **Site icon (owner pick, Oct 26):** "Rising rating + football" (`docs/icons/3a-rising-rating-football.svg`, also `web/public/favicon.svg`): the lime rating line climbing to a football on a dark tile. It stays readable at 16 px and says "football" without context; it also sits next to the title on the Start card. Original artwork. The other candidates (pitch-green variant, Spotlight, Mini pitch) are kept in `docs/icons/`.
- **Ball (owner, Oct 26):** bigger (radius 1.05 m against 1.75 m for a dot) and patterned like a football, so it is easy to find. It is drawn at its true position. Drawing a carried ball on the rim of the carrier's dot, to keep the shirt number visible, was tried and dropped: following the carrier's direction made it swing around the dot on every touch, and goals looked unnatural. Covering the number while carried is the accepted trade-off.
- **Scrollbars and highlight icons (owner, Oct 26):** scrollbars are thin and grey (`scrollbar-color` in `index.css`) because the default white one glared on the dark UI; goal chips carry a football and penalty chips a penalty-area-with-spot icon, matching the card shapes on the yellow and red chips.
- **Analyst stat line wording (owner, Oct 26):** "Expected goals (xG) 0.48 · Distance covered 5.0 km" plus a tooltip, instead of "xG 0.48 · Distance 5.0 km". Both are running totals up to the playhead. "Covered" matches the full-time recap.
- **Shot flight (owner, Oct 26):** the GOAL banner used to show at the kick while the ball took a full second to reach the net, because `positions.json` has one ball sample a second and the pitch glides between samples (about 8 m/s for a shot that is really about 22 m/s). Now, for the ~0.4 s after a shot, the ball flies the event's own `from` -> `to` line at `speed_kmh` (`ballAt` in `match.ts`), holds at the target and eases into the next sample (no jump, tested on every shot in the hero match). The banner, net flash and score bar wait for the landing (`goalRevealT`). Frontend only; the simulator output is unchanged. Not delayed: shot line, xG chip, rating log row, goal count on the player card.
- **GOAL banner in the team colour (owner, Oct 26):** was a pale green-white strip with team colour only at the edges, identical for both sides; now solid team colour with white text, fading out at the ends. The banner also carries the shirt number ("GOAL - #9 G. Lima 39'"), as the highlight chips do. White on Azure is about 3.7:1 and on Redmond about 3.9:1, enough for large bold text (3:1).
- **Commentary storage and hosting (owner, Oct 27):** hero text and audio are files baked into the image (`data/commentary/`, `data/audio/`). No database. *Superseded the same day for the on-demand cache:* it was ephemeral at first, but it now persists on an Azure Files share (see "Persistent cache and an all-time cap" under Phase 3 build, and "Deployment"). Azure Container Apps is the submitted live link; the static saved replay also goes on Vercel as a backup during judging and the permanent link after the Azure credit ends.
- **Rating log rows replay their moment (owner, Oct 27):** a click seeks 4 s before the change (shorter than the highlights' 8 s, since one action needs less build-up) and keeps play state and the selected player.
- **Phone control bar in two groups (owner, Oct 26):** with the timeline on its own row, play, mute and clock stay left and speeds, gear and full screen go right, as in phone video players; everything packed left had looked lopsided.
- **Start overlay on phones (owner, Oct 26):** below `lg` the card was centered in a pitch box about half its height, so its top was cut off; it now covers the whole screen there (portal into `<body>`, since the pitch's container query would pin `position: fixed` to the pitch box) and scrolls when taller than the screen.
- **Tag spacing (owner, Oct 26):** the name tag and hover tag measure their text in the browser and keep the rating pill a fixed 0.7 m after it; the old letter-count estimate cramped wide names ("M. Thomas #10") and over-spaced narrow text ("· OVR 82").
- **Full screen and pitch-only hover (owner, Oct 26):** a full-screen button at the end of the playback bar puts the pitch box alone in fullscreen, as large as fits at its own shape (113:79, so a 16:9 screen gets side black bars of about 10% each; wider screens more). The control bar now wakes only on mouse moves over the pitch, not over the highlights row. It hides 1.5 s after the mouse stops, about 1.8 s with the fade (was 2.5 s; owner: 2 s or less, as in video players). The cursor hides with the bar, and only keyboard focus (`:focus-visible`) keeps a hidden bar showing: with `focus-within`, a mouse-clicked button (e.g. full screen) kept focus and pinned the bar open.
- **One mute button, in the playback bar (owner, Oct 26):** between play/pause and the clock, where video players keep it; it replaced the speaker icon in the commentary panel and the Mute row in the View popover, since it now silences the crowd as well as the voice.
- **Crowd audio (owner, Oct 26), built in Phase 2 instead of Phase 3:** eight wordless CC0 Freesound recordings. The murmur, goal roar, near-miss "ooh", conceded-goal "OHHH" and cheer are single takes trimmed from a live football stadium recording ("Sound Of Sankt Pauli", itmightgetloud), chosen to avoid any chant or club name (a rhythm check on the loudness curve flagged one chanting stretch, which is not used); gasp and boos come from a CC0 crowd session at GameSoundCon 2024 (ShangusBurger), plus a real referee whistle. A Redmond goal has no groan: the indoor groan clip (boosted 10x, room echo and hiss) sounded out of place next to the stadium takes (owner), so a Redmond goal plays the loudest, most anguished take of the stadium's "chance missed" recording (owner: the home crowd should be upset, not just quiet), then the murmur hushes for 10 s. No CC0 stadium clip of a home crowd conceding was found on Freesound. The second try used generic crowd clips for everything; dropped (owner): it sounded like a convention hall, not a stadium. The trimmed clips are AAC (`.m4a`, made with macOS `afconvert`, since no MP3 encoder is installed). First try was one pack recorded at a Dutch league match (Freesound 27815); dropped after one listen (owner): the Dutch voices and chants were too specific for a fictional league, and a synthesised whistle sounded like an electronic beep. CC BY packs (Gregor Quendel, paulw2k) and ElevenLabs' free tier were skipped because they need credit. Freesound's previews need no login; the rest are used as is and trimmed at playback: each clip starts where its loudness rises so the reaction lands 0.3 to 0.8 s after the moment (the first version started clips 1.3 to 2.3 s early and sounded late), with measured per-clip level matching. Fouls and offsides no longer whistle (too frequent). Cards and the penalty always whistle, at every speed, louder (0.6) and 0.4 s ahead of the crowd (owner: it was masked by boos starting at the same instant). Above 1x reactions are shortened in proportion to the speed, at least 2.5 s (owner: a 12 s roar spanned about 48 match seconds at 4x); the pitch is not changed, since a sped-up crowd sounds like chipmunks and 0.4 s at 30x would not read as a roar. Under Phase 3's commentary voice the crowd will be ducked to about 35% (knobs in `CROWD`). Ball-kick sounds were left out (constant tapping at speed, competes with the voice). Rules: `crowdCues` in `web/src/lib/crowd.ts`; knobs: `CROWD`, `CROWD_CLIPS`.
- **Dev data serving (replaced in Phase 3 by the FastAPI proxy; the plugin is deleted):** a small Vite plugin served `/data/...` from the repo-root `data/` and answered `GET /matches`, mirroring `LIBRARY` in `sim/library.py` (backup hero excluded). A dev-only `window.__playerLens` handle (clock and select) exists for scripted visual checks and is stripped from production builds.

## Phase 3 build (Oct 27)

Choices made while building the agents and backend, where the docs left room. Knobs: `agents/config.py`; env: `app/settings.py`.

- **Six agents kept (owner).** Interpreter and Moments are the thin ones (code builds the facts, the schedule and the importance; the model only labels facts and sets tone and a reason), kept as cheap batched calls for the multi-agent criteria. A seventh prompt, `recap`, words the full-time recap; it is not one of the six.
- **Interpreter labels code-built facts** instead of producing them, so numbers can never come from a model. Labels with digits or player names are dropped.
- **`app/` follows Spec: Deployment**, not ARCHITECTURE's `/api/`.
- **Voices (owner, by ear):** English `en-GB-Ollie:DragonHDOmniLatestNeural` for Casual and Analyst, Spanish `es-MX-Jorge:DragonHDOmniLatestNeural` for both, all male. Changed Oct 27 from the plain `DragonHDLatestNeural` voices: plain HD ignores `<prosody>`, `<emphasis>` and express-as, so a goal sounded flat; the Omni versions accept `mstts:express-as` styles (14 emotions kept) and `temperature;top_p;cfg_scale`. Omni is billed on the same "Neural HD Text to Speech Characters" meter, $22 per 1M characters (checked against the Azure Retail Prices API; standard neural is $15). Pauses and emphasis markup are off (owner: odd pauses before units); units are spoken in full ("kilometres"). The Voice Director picks one style per line, and code enforces the rules: the emotion fits the side (good, bad or neutral for Azure City), the ball's danger, a mood that carries from line to line and fades (75 s), a louder voice near goal and for cards, and no minute mentions before 85'. A clip of a 9 to 12 word line runs 3.5 to 5.6 s, so the Commentator aims for 8 to 12 words.
- **Model endpoint is the v1 API** (`.../openai/v1/`): no api-version, the deployment name goes in the request body, only the host of `AZURE_OPENAI_ENDPOINT` is used. `gpt-4.1-mini` on Global Standard (retirement date April 2027, after judging).
- **Spend control:** no cost API exists and Azure's cost page lags, so every live call appends exact tokens, characters and dollars to `data/spend_ledger.jsonl` (gitignored); `scripts/spend.py` totals it. Visitors are gated by the all-time live cap; offline scripts by a hard `--max-usd` run limit that refuses the next call, and a chunk stopped by a limit is never stored as if the model wrote it. Tests use a fake model and Speech.
- **Persistent cache and an all-time cap (owner, Oct 27).** Any player can be clicked, so on-demand chunks must survive restarts or each redeploy pays for them again (and resets the ledger). The on-demand cache and the ledger go to `PERSIST_DIR`, an Azure Files share mounted into the container: the only permanent storage Container Apps can mount, so the app keeps plain files. Rejected: Blob Storage (upload code and URL serving), Cloudinary (SDK, keys, wrong home for a ledger; a CDN buys nothing for 24 KB clips), a database (out of scope). Because every chunk is paid for once, total spend is bounded by full coverage (about $123), so the two daily caps became one all-time `LIVE_CAP_USD` just above it: a daily cap would leave later visitors with template lines and no voice.
- **Fact Guard** is pure code (`agents/fact_guard.py`): numbers, roster and team names, `sim/blocklist.txt`, action words per fact kind in EN and Mexican Spanish, word count, early-result claims, plus units and location words for the Personalizer variants. The model only fixes a line the validator rejected; the validator runs again on the fix. Subjective claims ("what a legend") are not detectable by a validator and are left to the prompts.
- **Goal timing:** the backend emits a goal line at the kick's second; the frontend re-times it with `shownAt` when chunks arrive, so it shows when the ball lands, with the banner. The reaction stays 8 s after the goal.
- **Offline fallback kept:** `buildLines` in `web/src/lib/commentary.ts` is the fallback when the network itself fails (the saved replay has no backend). An HTTP error or a 202 makes the panel retry instead.
- **Playback bug found by the Chrome check:** Agent Framework copies the message between steps, and the job carried the whole match, so a template chunk took 1.4 s. `MatchBundle` and `PlayerPlan` now share themselves on copy (7 ms).
- **Recap** is words from the model checked against code-computed facts (goals, assists, rating, distance, off-ball credits, result), with a code template as the fallback; the full-time card keeps its own template for an unreachable backend and offers a "Listen" button when the recap has audio.
- **`.env` is never read by the agent** (owner rule, enforced in `.claude/settings.local.json`); scripts load it themselves. `.env.example` still needs two edits by the owner: a note that the API version is not needed, and `SPEECH_PRICE_PER_1M_CHARS=22`.

The container runs as root so the SMB share is writable without uid options. `scripts/deploy.py` keeps the app's current `LIVE_CAP_USD` unless `--live-cap` is passed, so a redeploy can't switch live AI off by accident. Lima's pre-generated files ship inside the image (copied from the local `data/` at build time), not on the share; whether they stay committed to git is still open (owner: decide later).
